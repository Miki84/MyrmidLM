    Beispielsätze

    Ein kleines Embedding-Modell vergleicht jede Anfrage mit diesen Sätzen; die Kategorie mit dem ähnlichsten Satz entscheidet. Ziel kann „schnell“, „groß“ oder ein Modell per Name sein (z. B. ein Coder-Modell für Code). Ein Satz pro Zeile.

      Fachgebiete

      Anfragen eines Fachgebiets gehen an ein bestimmtes Modell, z. B. Programmieren an ein Coder-Modell, Berichte an ein Modell, das gut schreibt. Erkannt an Stichwörtern in der Anfrage (die letzte Nachricht zählt doppelt). Ein Fachgebiet ohne Ziel tut nichts; ist sein Modell nicht bereit, verteilt der Router wie sonst. Funktioniert auch ohne schnelles Modell. Bilder, Hintergrundaufträge und Anfragen mit festem Modellnamen gehen vor.

      Externe Server

      Andere OpenAI-kompatible Server im Router, z. B. Strata oder vLLM auf einem PC im Netz. Clients erreichen sie über den Namen; mit Rolle „schnell“ oder „groß“ entscheidet auch der Router über sie.

          Hilfe
          Die wichtigsten Befehle und Hinweise. MASTER steht für die Adresse des Masters (hier: …). Befehle mit sudo auf dem jeweiligen PC ausführen.
          Clients anbinden (API, Key, Modellname)

          OpenAI-kompatible Adresse: http://MASTER:8080/v1. Modellname myrmid (der Router entscheidet) oder ein Name aus der Router-Tabelle (dieses Modell gezielt). Den Schlüssel zeigt auf dem Master:

          sudo myrmid key

          Schnelltest von einem anderen PC:

          curl http://MASTER:8080/v1/chat/completions \
  -H "Authorization: Bearer KEY" -H "Content-Type: application/json" \
  -d '{"model":"myrmid","messages":[{"role":"user","content":"Hallo"}]}'

          Hermes (~/.hermes/config.yaml): unter providers: einen Eintrag mit base_url: http://MASTER:8080/v1 und key_env: MYRMID_API_KEY; Hilfsmodelle (z. B. auxiliary.compression) brauchen mindestens 64K Kontext. Open WebUI: Einstellungen → Verbindungen → OpenAI-API, Adresse und Key wie oben.

          Jede Antwort trägt den Header X-Myrmid-Backend (welches Modell auf welchem Rechner). Mit X-Myrmid-Route: big oder fast legt ein Client die Rolle selbst fest.

          Installieren und Rolle ändern

          Installation (und erneut ausführen, z. B. nach einem Treiber-Neustart):

          curl -fsSL https://raw.githubusercontent.com/Miki84/MyrmidLM/main/install.sh | bash

          Ohne Fragen, z. B. als Worker: … | bash -s -- --role worker --yes. Alle Optionen: bash install.sh --help.

          Rollen: Master (Router + Dashboard, eigenes Modell optional), Host (lädt ganze Modelle für den Router), Worker (leiht seine GPU einem Master). Ein Host wird in seiner Karte per „Zum Worker machen“ umgestellt und umgekehrt.

          myrmid --version
myrmid detect          # Geräte, freier Speicher, Bandbreite
          Updates

          Am einfachsten im Bereich Version der Übersicht: „Jetzt prüfen“, warten bis alle PCs gebaut haben, dann „Jetzt auf … umstellen“. Mit „Automatisch aktualisieren“ passiert das nachts, sobald zwei Minuten lang keine Anfrage läuft. Kommt ein Dienst danach nicht hoch, geht der PC von selbst zurück.

          myrmid update                # Stand
sudo myrmid update check     # neue Version suchen und bauen
sudo myrmid update activate  # umstellen
sudo myrmid update rollback  # zurück zur vorigen Version
journalctl -u myrmid-update -n 50 --no-pager

          Der Build braucht mindestens 3 GB freien Platz unter /opt/myrmid.

          Dienste und Logs 
          systemctl status myrmid-server    # Master
systemctl status myrmid-host      # Host
systemctl status myrmid-worker    # Worker
journalctl -u myrmid-host -n 80 --no-pager
journalctl -u myrmid-server -f    # laufend mitlesen

          Strata: tail -f /var/log/myrmid/strata.log, Updates und Neueinrichtung in /var/log/myrmid/strata-update.log. Einstellungen liegen in /etc/myrmid/myrmid.conf, Messwerte und Zustände unter /var/lib/private/myrmid (dort nur im Ordner models löschen).

          Modelle, GPUs, Autotune 
          myrmid models                 # Modelle hier und zum Herunterladen, nach Eignung
myrmid download qwen3-4b      # Katalogname, Nummer aus „models“ oder user/repo:QUANT
nvidia-smi --query-gpu=index,name,pcie.link.gen.current,pcie.link.width.current --format=csv

          Aufteilung (Host-Karte, ab zwei GPUs): ein Modell über alle GPUs, jede GPU ein eigenes Modell, oder GPU-Gruppen (ab drei GPUs, z. B. drei Karten für ein großes Modell, eine für ein schnelles).

          Autotune misst die schnellsten Einstellungen für das geladene Modell; vorher „Konfiguration sichern“. Nach Hardware-Änderungen (andere Karte, anderer Steckplatz) erneut laufen lassen. Zeigt eine Karte weniger als x16, ist sie oft im falschen Steckplatz.

          KV-Cache: q8_0 braucht halb so viel Speicher wie f16, praktisch ohne Verlust; K und V immer gleich (MyrmidLM setzt beide). CPU-Takt fest auf Leistung (Hosts mit CPU-Anteil):

          sudo systemctl enable --now myrmid-cpu-performance
          Strata 
          sudo myrmid strata install --user NAME   # Strata klonen, einrichten, einbinden
sudo myrmid strata setup                 # vorhandenes Strata einbinden
myrmid strata                            # Stand
          • Laden dauert 2–3 Minuten (Experten in den RAM); der PC kann dabei kurz kaum reagieren. Einmal „Laden“ klicken und warten.
          • Kontext und KV-Cache: in der Host-Karte unter „Strata-Einstellungen“ (richtet die Konfiguration neu ein).
          • GPUs: in der Karte wählen; für geteilte Modelle empfiehlt Strata ab 8 GB je Karte.
          • Nach „Strata aktualisieren“ im Log prüfen, ob alle Karten dabei sind (layer split across GPUs).
          Router: wer antwortet
          • Rollen: groß (Standard), schnell (kurze, einfache Anfragen), nur per Name.
          • Wer entscheidet: Regeln (Tools, Bilder, lange Anfragen → groß), schnelles Modell (ordnet selbst ein) oder Beispiele (Ähnlichkeit zu Beispielsätzen). Braucht ein Modell mit Rolle „schnell“.
          • Fachgebiete: z. B. Programmieren → Coder-Modell, per Stichwörtern. Geht auch ohne schnelles Modell.
          • Hintergrundaufträge von Open WebUI (Titel, Tags, Folgefragen) gehen ans schnelle Modell.
          • Bei Gleichstand antwortet die kühlere GPU. Den Grund jeder Entscheidung zeigt der Monitor („Entschieden durch“).
          • Wartungsmodus nimmt einen Host aus dem Routing, ohne ihn zu wecken oder schlafen zu legen.
          Fehlerbehebung

          Platte voll:

          df -h /
sudo ncdu -x /                              # größte Ordner (apt install ncdu)
sudo rm /var/crash/*                        # Absturzabbilder, oft 30 GB und mehr
sudo systemctl disable --now apport         # keine neuen (Ubuntu)
docker builder prune -af                    # Build-Cache der CUDA-Builds

          Download von Hugging Face hängt (meist kaputtes IPv6): IPv4 bevorzugen.

          echo 'precedence ::ffff:0:0/96  100' | sudo tee -a /etc/gai.conf

          Uhr geht falsch (Logzeiten, nächtliche Updates):

          timedatectl
sudo timedatectl set-ntp true
sudo timedatectl set-timezone Europe/Berlin

          401 / invalid api key: Key mit sudo myrmid key neu kopieren (Verwechslung 0/O, l/I). 503 / kein Modell: Host schläft, ist in Wartung oder lädt noch: Host-Karte ansehen. Speicherfehler beim Laden: der Host versucht von selbst kleinere Stufen (weniger Cache, kleineres -ub, weniger Kontext) und zeigt es in der Karte; KV-Cache q8_0 oder weniger Kontext hilft.
